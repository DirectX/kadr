# Kadr

Минималистичная студия для вебинаров: **«интересный вебинар без помощника»**.

Экран спикера + камера в кружке справа снизу → запись в файл и/или выдача
готового кадра в **виртуальную камеру** (любое приложение видеосвязи выбирает
её как обычную веб-камеру). Дальше — автопереходы между планами, шаблоны
титров и эмодзи: приложение само работает «режиссёром» эфира.

Аналог идеи с низким порогом входа: Loom + OBS, но без слоёв, сцен и микшеров —
одно окно, три кнопки.

## Платформа

Только **Linux / Wayland** (осознанно: минимум абстракций). Требуется
`v4l2loopback` для вирт-камеры:

```bash
sudo modprobe v4l2loopback video_devices=/dev/video20 card_label="Kadr Cam" formats=yuyv
```

Аудио: v4l2loopback — только видео. В конференциях микрофон выбирается
отдельно (вирт-пары «камера+звук» как на Windows в Linux нет) — это учтено
в будущем мастере настройки (возможно через `pw-loopback`-монитор).

## Архитектура

```
[capture-потоки]              [render-loop]                 [потребители]
 screen: portal+PipeWire ─┐                                  ┌→ превью (окно)
 camera: v4l2             ─┼→ FrameSlot (свежий кадр) ─→ wgpu композиитор ─┬→ ffmpeg → mp4
 mic / system: PipeWire   ─┘                     (сцены, маски, твины)   └→ v4l2loopback → /dev/videoN
```

Ключевые решения:

- **Сцена-композиитор, а не плеер с оверлеями.** Граф: 1 фон-слой + N
  overlay-слойных слоёв (текстура + rect/маска + трансформация с твином).
  Все выходы читают один скомпонованный кадр (offscreen RT фиксированного
  размера — «canvas трансляции»). Сцена декларативна → переходы и шаблоны
  дёшевы (интерполяция между layout).
- **«Окно»/«область» = кроп монитора** в композииторе, а не отдельный захват:
  на Wayland window-capture через portal работает нестабильно, кроп — математика.
- **Захват экрана**: xdg-desktop-portal ScreenCast → PipeWire (crate `ashpd`),
  импорт в wgpu-текстуру. Самая сложная часть MVP.
- **Кодирование**: ffmpeg-subprocess (pipe rawvideo → libx264/VAAPI + AAC),
  не связки: проще, стабильнее, бесплатные апгрейды до аппаратного кодирования.
- **RTSP/SRT-раздача** — отдельным этапом после вирт-камеры и записи
  (RTMP/SRT через ffmpeg — дёшево; нативный RTSP-сервер — через GStreamer,
  если понадобится pull-модель).
- UI: **egui** (панель) поверх собственного wgpu-прохода; immediate mode
  подходит видеотайлам. GPUI — нет: не публикуется, нет интеграции с wgpu.

## Стек

Rust · winit · wgpu · egui/egui-wgpu/egui-winit · ashpd (в плане) · v4l (в плане) ·
ffmpeg subprocess (в плане) · v4l2loopback (вирт-камера) · PipeWire.

## Запуск

```bash
cargo run                 # debug
cargo run --release       # релиз
RUST_LOG=debug cargo run  # логирование
```

В коде — два тест-паттерна вместо захвата экрана («сетка со свипом») и
оживают реальные v4l2-камеры. Пресеты сцены слева: «loom», «спикер»,
«спикер полный», «только экран» — демонстрируют переходы и кроссфейды.

## Роадмап развития «режиссёра»

Порядок переставлен по приоритету продукта (решение пользователя):
сначала авторежиссура, захват экрана — на десерт.

1. **Трекинг лица** (быстрый ONNX, чисто в Rust): центрирование спикера
   внутри круга/фуллскрина, основа для будущего auto-zoom. Одна камера —
   уже интересно; мульти-камера усиливает.
2. **Мульти-камера как концепция**: вспомогательные камеры (сбоку, над
   столом) как полноценные слои сцены + переключение триггерами. Киллер-
   фича авторежиссуры: «режиссёр» выбирает ракурс, как живой оператор.
3. **Шаблоны подачи**: layout-пресеты (JSON), lower-thirds, титры-плашки,
   «спойлер-затемнение», эмодзи-реакции по хоткею.
4. **Триггеры автопереходов**: голосовая активность (VOX), закладки
   таймлайна, hotkeys. Правило: `событие → переход в layout`.
5. **Субтитры и фон**: whisper.cpp в кадр; размытие/замена фона.
6. **Раздача**: RTMP/SRT-push, RTSP-сервер.
7. **Захват экрана** (portal + PipeWire) — в самом конце: технически самый
   тяжёлый кусок, но концептуально это ещё один источник, а не новая механика.

## Этимология

«Кадр» — и единица видеопотока, и «быть в кадре». Kadr сам решает, что
попадает в кадр.
